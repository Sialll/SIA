# SIA 판매용 IA / UI 개편안

기준일: 2026-03-11

이 문서는 현재 SIA를 개인 판매용 제품으로 전환하기 위한 정보 구조(IA)와 화면 구조 초안이다.

## 1. 목표

- 일반 개인 사용자가 `메인 화면 하나`에서 핵심 흐름을 이해할 수 있어야 한다.
- 관리자용 진단 화면은 유지하되, 사용자 메인에서 분리한다.
- 실시간과 오프라인 점수의 차이를 명확히 보여준다.

현재 상태 메모:
- `메인 / 종목 / 백테스트 / 설정` 구조는 이미 반영됨
- 판매용 마감에서 남은 것은 시각적 완성도와 설치 흐름 정리

## 2. 제품 구조

### 사용자 영역

1. 메인
2. 종목
3. 백테스트
4. 설정

### 관리자 영역

1. 데이터 품질
2. readiness
3. factor breakdown
4. research
5. report hub

핵심 원칙:
- 사용자 영역은 제품처럼 보여야 한다.
- 관리자 영역은 내부 운영 도구처럼 남겨도 된다.

## 3. 사용자 메인 구조

### 상단 바

- 제품명
- 현재 시장 상태
- 마지막 갱신 시각
- 도움말
- 설정 진입

### 메인 탭

1. 실시간
2. 오프라인 점수
3. 백테스트

관리자 체크는 메인 탭에 두지 않는다.

## 4. 메인 화면 섹션 제안

### A. 오늘의 상태

- 현재 시장 열림/휴장
- 관심 종목 수
- 실시간 반영 종목 수
- 마지막 저장 점수 시각
- 텔레그램 연결 상태

### B. 관심 종목 관리

- 티커 추가
- 티커 삭제
- 시장별 일괄 붙여넣기
- 현재 관심 종목 미리보기

입력 규칙:
- 사용자는 `INTC`처럼 티커만 입력
- 버튼이 `추가/삭제` 의도를 결정

### C. 실시간 점수 카드

카드당 표시:
- 티커
- 현재 점수
- 현재 판단
- 신뢰도
- 감점 요인
- 최근 뉴스 한 줄
- 최근 가격 흐름

### D. 오프라인 점수 카드

카드당 표시:
- 티커
- 마지막 저장 점수
- 마지막 저장 시각
- 저장 차트
- 감점 요인
- 저장 근거

목적:
- 휴장일에도 사용자가 종목 상태를 읽을 수 있게 함

### E. 누락 사유

종목이 메인에 안 보이면 반드시 이유를 보여준다.

예:
- 시장 휴장
- 스냅샷 대기
- 가격 데이터 없음
- source 불일치

## 5. 종목 상세 화면 제안

종목 상세는 장기적으로 별도 화면으로 분리하는 것이 맞다.

### 종목 상세 구성

- 상단 요약
  - 점수
  - 판단
  - 신뢰도
  - 리스크
- 차트 구간
  - 최근 가격
  - 저장 차트
- 점수 분해
  - 차트
  - 매크로
  - 이벤트
  - 뉴스
- 감점 요인
- 상승 요인
- 최근 뉴스
- 최근 알림

## 6. 백테스트 화면 제안

사용자용 백테스트는 관리자 리포트처럼 복잡하면 안 된다.

### 사용자용 백테스트에서 보여줄 것

- 최근 성과 요약
- 표본 수
- 현재 해석 가능 여부
- 가장 강한 factor
- 경고:
  - 표본 부족
  - 데이터 품질 주의

### 관리자용으로만 남길 것

- raw readiness table
- source mismatch 상세
- strict alignment 세부
- tuning compare 상세

## 7. 설정 화면 제안

사용자 설정은 이 정도면 충분하다.

- 텔레그램 연결
- 활성 시장 선택
- 관심 종목 관리
- 기본 유니버스 포함 여부
- 알림 켜기/끄기

숨길 것:
- launchd
- cache path
- 내부 command
- report hub
- 내부 리포트 경로

## 8. 도움말 설계

도움말은 우측 상단에 두고 아래 내용을 설명한다.

### 도움말 핵심 문구

- 점수는 0~100점
- 점수는 차트/매크로/이벤트/뉴스를 합산
- 실시간 점수와 오프라인 점수는 다를 수 있음
- 감점 요인은 음수 기여 항목을 따로 보여줌
- 데이터 부족 시 해석을 보수적으로 해야 함

## 9. 한국어 라벨 방향

### 유지 권장

- 메인
- 오프라인 점수
- 감점 요인
- 관심 종목
- 마지막 저장 점수
- 시총 상위 종목 보고서

### 피해야 할 표현

- 너무 직역한 영문 기술 용어
- `strict` 같은 내부 용어의 전면 노출
- `hub`, `snapshot`, `factor` 같은 표현의 과도한 사용자 노출
